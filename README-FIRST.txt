One Browser 2.0.7 Windows x64 便携版

首次运行：解压到可写目录，打开 OneBrowser.exe。进入「内核管理」，下载或导入 Chrome / Firefox Windows x64 内核；添加窗口后即可启动。初始包不包含浏览器内核。

客户端升级：窗口管理页右上角「客户端升级」显示当前版本与 GitHub 最新正式发布版本，每周静默检查一次，也可手动检查。发布源为 https://github.com/onefom/ONE-Browser/releases 。只有仓库版本更新、且提供对应完整版时才显示下载入口，不会自动降级或覆盖运行中的程序。点击「下载新版」后通过系统浏览器下载完整版。

替换客户端：退出程序及全部浏览器，备份整个 data，从新版完整版取出 OneBrowser.exe 覆盖原程序，并同步替换 OneBrowser.ico。保留原 data、chrome、bin 和 config.yaml，不要初始化系统。

内核管理：右上角「管理内核」选择 Chrome 或 Firefox，分别连接其官方发布源检查更新和下载。已安装多个版本时，创建/编辑窗口可指定版本；新版内核不会自动替换已有窗口的选择。Firefox 更新只接受有效版本标签及同版本的 Windows x64 内核包，不会把字体包作为内核。已关联窗口的内核不能删除，需先通过齿轮 → 编辑窗口更换版本；运行窗口需先停止。外部导入目录删除时仅取消关联，保留外部文件。

内核状态：「已关联 X 个窗口 · 内核完整」表示必要启动程序、运行库和资源文件存在且非空，不等同于签名、全部文件内容或网站兼容性校验。文件缺失时会显示对应状态。

窗口数据：每个窗口使用独立持久目录，正常关闭后保留 Cookie、密码、网页会话和本地数据。运行中禁止删除窗口；关闭后删除窗口会一并删除对应数据。Firefox 与 Chrome 数据分开保存，切换内核不自动迁移登录状态。

插件：默认关闭。点击卡片右侧圆点，勾选窗口建立关联，取消勾选解除关联，保存后生效；再次打开会勾选当前已关联窗口。圆点高亮表示已关联窗口。新建和复制窗口默认不关联插件；导入 CRX/ZIP 后也需选择窗口。运行中窗口默认下次启动生效，勾选重启后尝试正常关闭并重新加载。删除使用中的插件前需先停止关联窗口。Chrome 插件不适用于 Firefox，Firefox 扩展请在其浏览器内安装。

窗口齿轮菜单：重启、编辑、复制、删除。重启使用同一数据目录；正常关闭失败则取消重启。浏览器按钮、内核列表和管理面板的 Chrome / Firefox 标识表示对应家族。

标题栏图标：便携包保留 OneBrowser.ico，EXE 也包含图标资源；程序在窗口就绪后加载标题栏图标。自定义品牌标识仍在系统设置中管理。

验证：真实在线发布源检查、客户端版本与下载资源筛选、每周限频、下拉选择、图标对齐、插件圆点与主题布局测试通过；Go 测试、Windows vet、前端构建及 Windows EXE 资源检查通过。Windows 标题栏实际显示与客户端实际下载请在 Windows 上验证。

发布规范：客户端正式版 tag 使用 v2.0.7 形式，资源名使用 OneBrowser-2.0.7-windows-x64-portable.zip。源码包不作为客户端升级资源。仅提供完整版和源码。

详细变更见 GITHUB-RELEASE-2.0.7.md；开发测试文档仅保留在源码包中。

2.0.5 本次界面修订（版本不变）：
- 内核家族简介紧贴名称，删除内核仅保留回收站图标，保留可访问名称、提示、关联保护和二次确认。
- 窗口配置悬浮卡片按窗口当前 coreId 读取实际 Chrome / Firefox，与启动图标同步。
- 内置与导入插件移除重复选择窗口按钮，圆点统一打开关联编辑，支持增加、取消、清空和回显已关联窗口；取消不保存，失败保留已成功状态与未成功关联。
- 插件关联未变化的窗口不重复写入或重启。明确选择重启时，仅重启关联已变化的运行窗口。
- 内核导入说明、账号空状态和插件导入说明统一为 13px 标题、11px 辅助文字；插件导入区使用左文右按钮，无加号图标。
- 回归覆盖内核名称同步、简介间距、图标删除保护、关联编辑增减清空、插件导入/改名/部分失败/重启/持久化及多主题窄窗布局。

2.0.5 管理说明栏与账号归档（版本不变）：
- 内核、代理、账号、插件四个页面统一说明区：13px 标题、11px 辅助文字、相同背景/间距/圆角，以及 40px 高文字按钮；统一去掉图标，深色模式同步适配。
- 账号页提供导入/导出。导出为真正的 RAR5 归档，使用存储模式，无外部程序依赖；账号字段为账号ID、名称、登录密码和备注，文件未加密。导入支持本程序导出的 RAR 或其中 accounts.json。
- 导入全批校验、CRC 校验、16MB/5000 条限制；相同资料跳过、ID 内容冲突分配新ID、不覆盖已有账号、不带入窗口绑定；取消或无效资料不修改现有账号。
- 自动化覆盖四栏文字、按钮与窄窗主题布局，以及账号导入/导出/重复/冲突/无效批次/失败/取消/重载保存；RAR 另由独立 libarchive 读取器验证。
- IP 变化提醒已加入：系统代理运行窗口按实际启动路由共享检测，独立代理跳过；由用户选择继续使用或关闭受影响窗口，不自动关闭。

2.0.5 IP 提醒与配色修订（版本不变）：
- 内核版本与关联信息间距缩小，删除图标在内核条目内上下居中。
- 薄荷预设替换为宝蓝 #071FD9；晨雾渐变色块固定为自身预设，切换主题不会改变其颜色。
- 后台每 60 秒检测系统代理窗口的 IPv4 出口；同一路由共享检测，发现变化后间隔 2 秒复核，确认相同的新 IP 后提醒。首次只建立基准；超时、限流或无效响应不替换基准，不通过直连回退绕过代理。
- 单个提醒展示变更前后 IP、国家及受影响窗口。提醒未处理时不重复弹出；继续使用保留窗口，关闭仅停止该提醒中仍处于同一次运行的窗口，新开或已重启窗口不受影响。
- 国家仅在建立基准或确认变化时查询；无运行窗口不发起检测，国家查询失败显示未知地区。检测不是实时断网保护，通常有约 2–65 秒确认延迟（服务超时或失败时会更久），关闭前留意未提交内容。
- 浅色、深色、窄窗预览与自动化布局/操作检查通过；Windows 上真实网络切换、托盘唤出及浏览器关闭需用户实测。

2.0.5 IP 检测节奏与便携包整理（版本不变）：
- 按用户要求保留每 60 秒常规检查；启动窗口后异步建立首次基准，同一路由共享检测，已建立基准的路由不因新开窗口重复请求。仅发现变化后短间隔复核，国家仅在首次或确认变化时查询。
- 使用单独的系统/独立代理标记识别监测范围，防止底层代理节点匹配改变代理ID后误跳过系统代理窗口；监测仅取运行状态快照，不生成启动码或重新扫描配置。
- 前端优先接收原生事件，每 60 秒及恢复焦点时补取未处理提醒，启动连接失败会重试。检测失败、恢复、建立基准和确认变化可在系统日志的 IPMonitor 记录中查看。
- 弹窗旧 IP 为蓝色粗体，新 IP 为紫色粗体，深色模式同步适配。
- Windows 完整版及后续发布不包含 CAMOUFOX-TESTING.md、STARTUP-REVIEW.md、TESTING-STATUS.md；这些开发文档保留在源码中。

2.0.7：
- IP 提醒旧地址使用标准字重、小一字号；新地址保持原字号和粗体，保留蓝/紫配色。检测间隔仍为 60 秒。
- 修复深色模式关闭磨砂时的设置开关和窗口配置按钮浅灰底。
- 高级设置五项操作增加成功/失败/取消、运行保护及数据保留验证。缓存清理支持 Firefox；配置导入先校验、保存失败回滚，不导入其他电脑的浏览器数据绑定；初始化要求关闭所有浏览器，保留内核。

2.0.7 深色界面细化（版本不变）：
- 磨砂与非磨砂共用冷灰蓝色阶；分别区分页面、卡片、弹窗、标题、配置分区及输入区，去除旧样式遗留的浅灰块。
- 统一创建/编辑窗口、添加账号、配置下拉、插件关联及确认弹窗；备份、客户端升级和内核管理浮层同步适配。
- 深色成功状态标签改为低亮度绿色底，删除操作使用暗红底与浅红文字；未安装内核使用中性状态。次级按钮、禁用和悬停状态统一。
- 关闭磨砂使用实色表面，不对遮罩和菜单增加模糊；开启时保留静态半透明层级。浅色样式不受本次深色样式影响。
- 自动化验证 3 种窗口宽度 × 2 种深色模式、创建/账号弹窗、下拉交互、备份/升级/内核浮层、状态与删除按钮、浅色隔离，并回归高级设置五按钮。

深色模式细节复核（2.0.7，版本不变）：统一应用预设/查看配置按钮及悬停、焦点、禁用状态；客户端升级与数据备份状态改为透明底色；内核安装状态和账号保护标签使用低饱和深色底。弹窗标题、配置区与输入区保持冷灰蓝层级，关闭磨砂时不使用半透明浅灰背景。测试覆盖构建产物页面与源码页面。

深色样式交付修复（版本仍为2.0.7）：构建按界面资源内容生成独立目录，页面、CSS、JS不再复用固定资源路径；关键深色样式随页面内嵌，避免外部样式陈旧时按钮、状态标签与配置区回退旧颜色。浅色样式不作调整；交付验证包含生产入口、旧外部CSS模拟及浅色模式对照。Windows WebView2实机结果仍需用户反馈，不以Linux浏览器测试替代。

深色空列表接缝修复（版本仍为2.0.7）：取消空窗口占位行的常态与悬停底色，避免占位行高度与列表容器不一致时出现横向色块接缝；保留普通窗口行、表头与外框，浅色模式不作修改。

2.0.7：Chrome / Firefox 内核分别按版本从新到旧排序，新建窗口、编辑窗口、内核管理卡片和版本下拉保持一致；排序不修改已有窗口内核绑定。
